## Context
MineCore needs a sourced requirements baseline so that every milestone is scoped
against what professional mining software actually offers. The researcher has no
repository access; the architect commits the document after review.

## Required behaviour
Survey Datamine Studio RM/EM/OP, Micromine Origin/Beyond, Deswik (CAD, Sched,
Pseudoflow), GEOVIA Surpac and Whittle, Maptek Vulcan, Seequent Leapfrog Geo/Edge.
Per engineering domain (drillhole data, geological modelling, geostatistics,
block modelling, resource reporting, open-pit optimisation, pit design,
scheduling, underground design, geotechnics, grade control, drill and blast,
interoperability, scripting/automation, visualisation):
- capabilities and workflows, with the products that document them;
- named methods (e.g. pseudoflow, ordinary kriging, RBF implicit modelling);
- file formats in and out;
- public user complaints or gaps (forums, reviews, papers) that MineCore could
  address better.

## Rules
Public sources only, each fact with a URL. Mark anything unverified as an
assumption. No proprietary or confidential content, no guessed internals.

## Out of scope
Pricing, marketing claims without technical content.

## Report back
One Markdown file `docs/research/CAPABILITY_MATRIX.md`: one table per domain,
then a "Gaps and opportunities" section, then the source list.
